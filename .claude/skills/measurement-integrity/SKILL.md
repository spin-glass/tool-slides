# Measurement Integrity

このスキルは、**数値が主張を支えているかを検査する**ために使う。計算が正しいかではなく、
**その数字がその主張の証拠になっているか**を見る。

最も避けたい失敗は、数字が出ないときに「出せない」と言わず、
**出せる形になるまで定義や標本を動かしてしまう**ことである。

## 使う場面

- 分析して数値を出し、資料・報告・意思決定に載せるとき
- 既存の数値を引用・監査するとき
- 評価用データセットを作る、または既存データを評価に流用するとき
- 数字を含むスライドや文書を作成・修正するとき

---

## 1. 三つの対応を検査する

数値を出す前に、次の連鎖が切れていないことを確認する。**どこか1つでも切れていれば数値を出さない。**

```
解きたい問題  →  指標  →  データ  →  出所
```

### 1-1. 問題と指標

- その指標が動いたとき、**解きたい問題が本当に解決したと言えるか**
- 指標が「測りやすいから選んだもの」になっていないか
- 問いの型と指標の型が一致しているか

| 問いの型 | 必要な指標 | 取り違えやすい代用 |
|---|---|---|
| 全体でどれだけ起きているか | 母集団に対する発生率 | 見つけた事例の件数 |
| ある条件下でどう振る舞うか | 条件付きの率 | 母集団率 |
| どこへ間違えるか | 分布・内訳 | 単一の代表値 |
| 改善したか | 同一集合での前後比較 | 別集合どうしの比較 |

### 1-2. 指標とデータ

- **その指標を計算できる形のデータか。** 分母になる母集団が定義できているか
- **選択バイアス**：データが「結果」で選ばれていないか。
  結果で選んだ標本から、その結果の率は推定できない
- **標本の同質性**：性質の違う標本を混ぜて1つの率にしていないか。
  出所ごとに率が大きく違うなら、混ぜた率は意味を持たない
- **層化標本**：母集団の構成比と違う比率で取った標本を、そのまま母集団の率として読んでいないか
- **分解能**：内訳や区間を語るのに十分な件数があるか。
  各分類が数件しかないなら、順位も割合も語れない
- **独立性**：モデルの評価なら、そのデータが学習に使われていないか
- **指標の混在**：1つの列・1つの語に別の指標を混ぜていないか。区分ごとの割合は「正解の側から見た割合」（recall）か
  「判定の側から見た割合」（precision）かを書き分け、「正解率」は全体の Accuracy にだけ使う
- **層化の偏り**：標本がどれかのモデルの判定で層を分けて抜いてあるとき、区分ごとの recall はそのモデルに有利に出る。
  recall を出すならその偏りを注記し、主には判定の側から見た割合（層ごとの precision）を使う

### 1-3. データと出所

- 一次データはどこにあり、いま参照できるか
- 誰が・いつ・どういう条件で作ったか
- **列の意味が一つに定まるか**。同じ値が複数の状態を兼ねていないか
- 時点をまたぐ比較なら、両時点のデータが同じ条件で取られているか
- 履歴のない上書き型のデータで、変化の**向き**を仮定していないか

## 2. 検出する問題

### データと指標の取り違え

- **定義上の帰結を測定値として出す**：選び方から自動的に決まる値を、実測したかのように書く。
  例「AIが誤った画像だけを集めた集合で、AIの正解率は0%」
- **結果で選んだ標本から率を出す**：誤りとして発見された事例の集合で誤り率を計算する
- **混合標本の率**：無作為抽出・狙い撃ち抽出・学習済みデータを混ぜて1つの率にする
- **層化標本を母集団率として読む**：特定の層を上乗せして取った標本の生の割合を、
  そのまま全体の率として提示する
- **別集合どうしの比較**：改善前と改善後で違うデータを使い、差分を改善幅と呼ぶ

### 定義の操作

- **結論が変わる方向への定義変更**：出した結果が意図と違ったとき、
  対象の定義を締めたり緩めたりして結果を変える。
  変更が必要な場合もあるが、**変更前後の両方の結果と、変更の理由を必ず併記する**
- **造語の持ち込み**：既存の語彙で表せるものに新しい名前を付け、そのまま成果物に載せる。
  既存文書にある語を使う。無い場合は定義を明記し、造語であることを書く
- **事後的な定義を事前登録のように書く**：データを見た後に決めた基準を、
  最初から決めていたかのように提示する

### 確認の不足

- **実物を見ずに機構を語る**：画像・ログ・レコードの中身を見ないまま、
  「こういう傾向がある」と原因を説明する。**対象を絞り直したら、絞り直した後の実物を見る**
- **標本の偏りを主題にする**：たまたま多かった型を、そのまま問題の本質として語る
- **一次データの所在を確認しない**：引用元が既に失われている数値を、追試可能なものとして扱う

---

## 3. 点検手順

1. **問いを一文で書く。** 誰が何を判断するための数字かを書く
2. **指標を一文で書く。** 分子と分母を明示する
3. **データの出所を書く。** 誰が・いつ・どう作ったか、どこにあるか
4. 上の三つを並べ、§1 の各項目に照らす
5. **標本を出所別に分解し、出所ごとに指標を計算する。**
   出所間で大きく違うなら、混ぜた値は使わない
6. **分解能を確認する。** 内訳の各分類の件数を数える。数件しかないなら割合を出さない
7. **実物を数件見る。** 特に、絞り込みや除外をした後は必ず見る
8. 区間を付ける。点推定だけを出さない

---

## 4. 止める条件

次のいずれかに当たるときは、**数値を出さずにその旨を報告する**。
定義や標本を動かして出せる形にしてはならない。

- 分母になる母集団が定義できない
- 標本が結果で選ばれており、その結果の率を問われている
- 分解能が足りない（内訳の各分類が数件）
- 一次データが失われ、追試も代替検証もできない
- 指標が問いに答えていない

報告の形は次のとおり。

> この問いに答えるには〈必要なデータ〉が要る。手元にあるのは〈実際のデータ〉で、
> 〈理由〉のため率として出せない。出せるのは〈代わりに言えること〉までである。

**「今は言えない」は成果である。** 出せない理由を明確にすることが、
誤った数字を出すことより価値がある。

---

## 5. 成果物への反映

- **数値が確定するまで、資料（スライド・報告書）に反映しない。**
  検討中の値を載せて後から差し替える運用にしない
- 数値はスクリプトの出力に現れるようにし、**文書に手書きの数字を残さない**
- 出所・分母・区間・標本の性質を、数値と同じ場所に書く
- 既存の数値を訂正するときは、**元の数値を消さず、なぜ誤ったかを残す**
- 新規のドキュメントを増やさない。既存の文書・資料に統合する

---

## 6. 検査の記録

数値を出したときは、次を残す。文書ではなく、スクリプトのコメントや出力に書く。

- 問い / 指標（分子・分母）/ データの出所
- 標本の性質（無作為か、層化か、結果で選ばれたか、学習に使われたか）
- 除外した対象と、除外の理由
- この指標で**答えられないこと**
