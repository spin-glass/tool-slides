# 主張の表（claims.csv）

設計書と確認型スライドは、この表から作る。表が正本で、本文はこの表の id を参照する。
`scripts/claims.py` が列と状態を検査し、slides の `lint_slides.py` はスライドの `<!-- claims: C1,C2 -->` を、
`check_doc.py` は設計書のフォルダの表を検査する。

## 列（この順）

| 列 | 書くこと | 例 |
|---|---|---|
| id | 主張ID。英字で始まる英数字 | C1 |
| doc | 原文の文書名。本人の説明や会議なら出所 | 運用・移行設計／経理部の定例 2026-09-20 |
| section | 原文の章・箇所。版が複数なら版も | §6.1–6.4／40–44行 |
| claim | 主張を1文で。原文の言葉を保ち、数値は単位・母数つき | 試験1か月→並行1か月→切替1週→定常3週で移す |
| status | 下の7つ | 想定 |
| evidence | 根拠（測定・原文の引用・決めた人と日付）。事実・決定には必須 | 経理部長の決定（2026-09-20 の定例） |
| owner | 決める担当（未決・提案のとき） | 経理課長 |
| target | 掲載先: doc / deck / both / none | both |
| note | 補足。矛盾する別の記述、注意点 | 原文は「上回る」と「以上」が混在 |

## 状態の見分け方

| 状態 | 意味 | 原文の例 → 書き方 |
|---|---|---|
| 事実 | 測定・記録で確かめたこと。測定日・出所（データ・集計表）がたどれる。原文が「実績」と書いていても出所が無ければ 参考値（note に「原文は実績と記載」） | 「要件表の参照先が本文と合わない（40–44行）」→ 事実（レビューで照合） |
| 参考値 | 原文に数値があるが、測定条件が残っていない・再測定前。数値の無い記述でも、原文が現状として述べていて照合できないもの（「現在は2名で手で回答」）はここ | 「実績 約1%（目安であり再集計する）」→ 参考値。実績と書かない |
| 方針 | 原文に「こうする」と書いてあること。実施済み・実績ではない。決めた人と日付が無い導入判断（ヘッジつきを含む）も 方針 | 「閾値は月次で評価・調整する」→ 方針 |
| 想定 | 見積り・仮の期間・仮の工数 | 「移行は3か月」「確認は1日20分」→ 想定。確約と書かない |
| 提案 | レビューで足した案。原文には無い。本人未採択なら note に書く | 「本番の設定に番号を付けて切り戻しの単位にする」→ 提案 |
| 決定 | 決めた人と日付がある決定。本人の原文を evidence に | 「決めた4点」→ 決定（経理部長、2026-09-20 の定例） |
| 未決 | まだ決まっていない。スライドでは `[要確認]{.tbd}` か「まだ決めていない点」の一覧に出す | 「保留」の上限の数値 → 未決（決める: 経理課長） |

状態を上げるとき（提案→決定、参考値→事実）は evidence に根拠を書き、黙って書き換えない。
決める担当（owner）が原文に無いときは「原文の作成者」と書く。作業を進めるために作業者が具体的な担当を置くときだけ「総務課長（仮）」の形にし、note に「仮」と書く（claims.py は未決・提案に担当が無いと warning を出す）。
設計書に載せず報告だけに回す主張（作業中に気づいた穴など）は target を none にする（`claims-unused` の対象外になる）。
矛盾する2つの記述（例: 基本設計 §4.2 と精度検証 §5.3 の判定規則）は、1行にまとめて note に両方を残すか、2行にして互いを note で指す。

## 使われ方

- スライドの各枚: `<!-- claims: C3,C8 -->`。未決（status 未決）の id を載せた枚は、`[…]{.tbd}`・`::: {.undecided}`・「確認中」「未決」の語のどれかで未決と分かる形にする（lint が block する）。
- 設計書: 正本の章の文の末尾に「（C3）」と id を1回だけ添える（要点・対照表・計画の表では添えず、正本の章を参照する）。§1 の「まだ決めていない点」の表は 未決 の行から作る。
- 付録: スライドの付録に id・主張・出所・状態の表を、`claims.csv` を読むコードセルで出す（手で写さない）。
