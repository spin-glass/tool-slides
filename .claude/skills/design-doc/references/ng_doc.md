# 設計書の冗長さの辞書

`scripts/verbosity.py`（`check_doc.py` から使う）がこのファイルの ```` ```ng:<class> ```` フェンスを読み、1行1正規表現として使う。
slides の `references/ng_words.md` の hedge（ヘッジ・言い訳）と buzzword（中身のない抽象語）も、設計書の文章に同じように当てる。
「」の中は語の引用なので数えない。語を足すときはフェンス内に1行追加するだけでよい。

| クラス | 何を見つけるか | 置き換え方 |
|---|---|---|
| generic | 一般論・心構え（誰が・いつ・何を・どの値で、が無い） | 担当・時期・数値・条件に置き換える。置き換えられなければ段落ごと削る |
| meta | 文書についての前置き（「本書では〜を説明する」） | 削る。見出しと冒頭の表が同じ役目をする |
| obvious | 言わなくても通じること（表を見れば分かる数・範囲、書き方の宣言、進行管理） | 削る。表・見出し・冒頭の表が同じことを示している |

数字・主張ID（C1）・章参照（§）・`コード`・「固有の語」・`[要確認]` のどれも無い段落にこれらの語があれば、`check_doc.py` は削除候補として止める（block）。
中身のある段落でも、2つ以上あれば warning。

## (c) 言わなくても通じること

2026-10-08 の改稿（判定仕様と表を持つ設計書3本）で落とした文の形。表や見出しがすでに言っていることの言い直し、書き方の宣言、
進行管理の記述は、読み手に何も足さない。実例（題材は一般化した）:

- 「本設計の完了条件は、上表の範囲を満たすことである」（範囲の表の言い直し）
- 「本書はこの3つを扱わない」（範囲の表と重複）
- 「実験の結果が出ていない箇所は、空欄にせず…併記する」「選択肢が要る箇所は『選択肢＋採る案＋判断材料』の形で書く」（書き方の宣言）
- 「ステータス Draft（§1〜§13 執筆完了）」（進行管理を冒頭の表に置かない。冒頭の表の「版」は版と日付だけ）
- 「要件は4つの束に分かれる」（表が4行）、「この方法で取れないものが3つある」（表が3行）。表の行数の言い直しは
  `table-dup`・`recounted-number` も知らせる
