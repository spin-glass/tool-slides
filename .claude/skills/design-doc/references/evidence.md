# やらないことと、その理由

`SKILL.md` から移した（2026-10-07）。規約の理由の詳しい説明は `design_doc_guide.md`。

- 要約で縮めない: 条件・例外・担当を言い換えて短くすると、そこが落ちる。段落を丸ごと削るか、繰り返しを1か所にまとめる。残す段落は主張の表に戻して組み替える。
- 構造を足して長くしない: 状態の列・主張ID・対照表・付録は読み手の道具だが、同じ事実を表ごとに書き直すと、一般論を消しても読む量が原文の2倍以上になる（2026-10-02 の試験で、Opus・Sonnet とも原文の約2.6倍になった）。
- 見つけた穴と案を本文に足さない: 同じ試験で、穴と案を本文に入れた2本は原文の2.3〜2.6倍、報告に回した2本は0.8倍前後だった。穴と案は本人が選ぶもので、本文に入れると決まったことと区別できなくなる。
- 一般論を残して「丁寧な設計書」に見せない: 中身の無い段落は、読み手が中身のある段落を探す手間を増やすだけで、何も決めていない（coherence 効果）。
- 原文に無い費用・日程・性能を補わない: 不確実な箇所ほど LLM は水増しする（verbosity compensation）。未決と書けば本人が埋める。
- 「決めてもらう」構成にしない: 本人の決定（2026-10-01）。どうするかはこちらで決め、意思決定者の時間は齟齬の確認に使う。
- 未決の印 `[要確認]{.tbd}` で placeholder の検査をすり抜けない: 一覧（`.undecided`）に載せて初めて許される。
- 複数の文書に同じ共通事項の全文を複製しない: 短い要点と、定義の正本・版への参照にする。
- 文書の説明で始めない: 「位置づけ」「読み方」「文書一覧」「記法」が本文の前に積み上がると、読み手は何も得ないまま降りる（14章・約1.6万字の運用設計で、本文の中身が始まるまでの約2300字が文書についての説明だった。冗長さの block を0にしても読む気が戻らなかった最大の原因）。冒頭は「扱うこと／読む人／原文／状態」の表と §1 だけ。
- 引く表を本文の途中に置かない、同じ型の章を続けない: 要件の一覧や未決の全一覧は付録に置き、章の型は章の問いで変える（同じ型が10章続いた文書では、進んでいる感覚が出ず、均等に撒かれた強調は何も強調しなかった）。
