## アクションタイトル: 悪例と良例

<example>
| 悪例 | 何が悪いか | 良例 |
|---|---|---|
| 売上の推移について | ラベル型。何が言いたいか分からない | 新プラン導入後3か月で売上は20%増えた |
| 課題 | 1語のラベル。どの課題が重要か分からない | 月末3日間の手入力が決算遅延の7割を占める |
| 請求書OCRの精度比較 | 体言止め。どれが良いのか結論がない | 請求書OCRはA社製が誤読率1.2%で最も低い |
| 今後の展望と取り組むべき施策の方向性について | 長い・ラベル型・中身がない | 来期は督促メールの自動化から着手すべきだ |
| まとめ | 終わりの合図でしかない | 試験導入の承認で月40時間の手入力を削減できる |
</example>

## 本文: before / after

### 例1 言い訳・前置きを削る

<example>
**before**

```markdown
## 請求書処理の現状について

- 本スライドでは、請求書処理の現状について説明します
- 様々な要因により、処理に時間がかかっている可能性があると考えられます
- 担当者へのヒアリングでは、手入力が負担になっているとの声もありました
- 一概には言えませんが、月末に作業が集中する傾向があるかもしれません
- 今後、ある程度の効率化を図ることが可能と思われます
- なお、詳細は別途ご説明いたします
```

**after**

```markdown
## 月末3日間の手入力が決算遅延の7割を占める

- 請求書 月1,200枚のうち 850枚が月末3日間に届く
- 手入力 1枚あたり平均2.5分、月末だけで35時間
- 決算遅延 過去6か月の平均2.1日のうち1.5日がこの工程

::: {.notes}
担当者3名へのヒアリングと、6か月分の処理ログから集計した。
:::
```
</example>

### 例3 数字は手で写さずコードセルで出す

<example>
```markdown
## 試験導入で月末の手入力は35時間から6時間に減る

```{python}
hours_before = 850 * 2.5 / 60
hours_after = hours_before * (1 - 0.83)
```

- 月末の手入力 `{python} f"{hours_before:.0f}"`時間 → `{python} f"{hours_after:.0f}"`時間
- 前提 自動読取率83%（A社試験の実測）
- 残る作業 手書き請求書の確認のみ
```
