# スライドの型 — Claude Design「スライド型見本」の部品

本文を書く前に、各枚の証拠の形から型を1つ選ぶ。型の見た目は `theme/custom.scss`（CSS の部品）と `scripts/figs.py`（図）に実装済みで、どのデッキでも同じ見た目になる。
型の出所: Claude Design「スライド型見本」（3デッキ28枚の棚卸し 2026-09-30、確認型 4a 2026-10-01）。

骨子（フェーズ2）で各枚に `<!-- type: pair -->` のように型を書き、本文ではその型の書き方を使う。
lint は、知らない型を止め（block）、型に必要な書き方が本文に無い枚・型を書いていない本編の枚を知らせる（warning）。

## 型の選び方

**先に図解の部品（`parts.*`）で描ける形かを見る。** 3点の並列・段階・流れ・数は、箇条書きでなく下の表の上から順に当てる。
`text` は、並び・流れ・数・前後のどれにも当たらないときだけ（本編の半数を超えると lint が `text-heavy` を出す）。

| 証拠の形 | 型 | 書き方（lint が探すもの） | 見た目 |
|---|---|---|---|
| 2〜4個の要素の並び（要点・役割・段階・案） | `cards` | `parts.cards([...])`（段階なら `arrows=True`、推す案は `highlight=`）か、縦の要点なら `parts.steps([...])` | 薄青のカード列（見出し＝青、番号＝橙）／番号付きの行。公式 Slides 型の「カード行・番号付きまとめ」と同じ |
| 手順・分岐・流れ | `flow` | `parts.flow("""D2""")` | D2＋ELK の図。revealjs では線の順に描く。pptx 主体なら `{mermaid}` のセル |
| 結論を1〜2個の数字で言う | `number` | `parts.stat(値, unit=, label=)`（pptx 主体なら `[値]{.big}`、未取得なら `[要確認]{.tbd .big}`） | 64px の太字、revealjs では数え上がる |
| 数の比較・推移 | `chart` | `parts.bars(...)`・`parts.echart_bars(...)`（pptx 主体なら `figs.bars(...)` か matplotlib のセル） | 主張の系列だけ青、残りは灰。構成比は `parts.stack`、人数は `parts.pictos` |
| 前と後・現行と変更後・A案とB案 | `pair` | `:::: {.columns .pair}` | 左＝前（灰の見出し）、`[→]{.arrow}`、右＝後（青の縦線と見出し）。前後の関係がない並列なら `.accent-left` |
| 条件と、満たす／満たさないときの扱い | `outcome` | `::: {.outcome}`（満たすほうに `.accent`） | 左に縦線、1行目＝条件18px、2行目＝結果を太字 |
| 担当・体制 | `roles` | `:::: {.columns .roles}` | 上辺に青の線、1行目＝担当を太字 |
| 期間・段階（日程つき） | `timeline` | `figs.timeline(...)` | 工程表。既定は青、注目させる段だけ橙 |
| 実測値の無い関係の向き | `direction` | `figs.direction(...)` | 「Aを上げるとBが減りCが増える」を棒の向きで。但し書き必須 |
| 項目×属性の対照 | `table` | Markdown の表、または表を出すセル | 24px・横線1px |
| 具体例の写真 | `images` | `imgfig.*_figure(...)` か `![…](…)` | SKILL.md「具体例の画像を並べる」 |
| 上のどれにも当たらない事実が3点まで | `text` | 箇条書き3つ（何もなくてよい） | タイトル＋箇条書き＋出典 |

型を足すために証拠を作らない（図に見せる数字が無いなら `chart` にしない。並びが2つ未満なら `cards` にしない）。
1枚に型は1つ。`pair` の右に数字を置きたくなったら、主張が2つ入っていないかを先に疑う。
`parts.*` は HTML を返すので、セルは `#| output: asis` で `print(parts.cards(...))`。pptx・beamer では文字だけになる（配布が revealjs の URL と `render_check.sh --pdf` の PDF なら見た目は同じ）。
`number` と `chart`、`table` と `outcome` のように主従がはっきりした組み合わせは、主のほうを `type` に書く（見本の4枚目は `outcome`、3枚目は `direction`）。

## 見出しの様式（既定＝章ラベル＋短い見出し）

```markdown
## 観測と判定を分ける {kicker="設計"}

[観測は何が写っているかの票、判定は版付きの規則で観測から導く最終カテゴリ]{.lead}
```

- 見出しは話題を言う1行の句（全角20字まで、体言止め可）。章ラベル（`kicker`）はデッキで揃えた語（問い／設計／運用／評価／根拠／限界／結論 など、全角8字まで）で、見出しの上に小さく橙で出る（`filters/kicker.lua`・`theme/custom.scss`）。
- この枚の主張（so-what）は本文の1行目に `[文]{.lead}` で書く。タイトル連読（`--titles`）は「章｜見出し」で出るので、骨子の承認では `.lead` の文も添えて論旨を確かめる。
- 完全文のアクションタイトル（旧来の様式）にするデッキは YAML に `title-style: sentence`（全角40字以内・述語で終える・体言止めは block）。確認型（`kind: confirm`）は常にこちら。

## 書き方

### cards（カード列・番号付きの要点）

```python
#| output: asis
#| fig-alt: "観測→規則（版付き）→判定の3段。観測は何が写っているかの票、規則は観測から機械的に導く、判定は最終カテゴリ"
print(parts.cards([("観測", ["LLM/VLM に複数回問う", "属性ごとに yes／maybe／no"]),
                   ("規則（版付き）", "観測から機械的に導く。基準変更＝版上げ"),
                   ("判定", "最終カテゴリ。規則版と発火した規則IDを記録")], arrows=True, highlight="規則（版付き）"))
```

```python
#| output: asis
print(parts.steps([("観測と判定の2層に分ける", "観測＝何が写っているかの票。判定＝版付きの規則で導く最終カテゴリ"),
                   ("ラベルは上書きせず、追記する", "出来事として残し、現在のラベルは規則版ごとのビュー"),
                   ("曖昧はクラスではなく状態", "投票分布をそのまま教師にし、残った曖昧群は規則の候補にする")]))
```

- `cards` は横に2〜4枚（本文は1枚3行まで）、`steps` は縦に2〜4行（結論の要点・手順）。`arrows=True` は段階・流れのときだけ。`highlight=` は推す案・いまの段階だけ（1枚）。
- 本文は文字列（1段落）か行の列。箇条の記号は付けない。数字を入れるならセルで計算した値を f 文字列で埋める。

### pair（前→後）

```markdown
:::: {.columns .pair}
::: {.column width="44%"}
### 現行

経理課が PDF を見て会計システムに手で入力

[打ち間違いは月次の照合まで見つからない]{.muted}
:::
::: {.column width="8%"}
[→]{.arrow}
:::
::: {.column width="44%"}
### 変更後

OCR で読み取り、自信がない項目だけ人が確かめる
:::
::::
```

- 左右の段落は同じ数・同じ順にそろえ、行ごとに対応させる（左の1行目と右の1行目が同じ観点）。
- 見出しは「現行／変更後」「前／後」「A案／B案」の2〜4字。段落は24px なので1段落は全角20字前後まで。

前後の関係がない A案 と B案 を並べるときは、矢印の列を外して `width` を 48%/48% にし、`.columns .pair` に `.accent-left` を足す。青の縦線と見出しが左の列へ移り、右は灰になる。

- 左を青にするのは「左を選ばせたい」という主張になる。中立に見せたいなら `.pair` を付けず `:::: {.columns}` だけで並べ、型は `text` にする（`.accent-left` を外しただけの `.pair` は右の列が青になり、右を勧めて見える）。
- 本文に `<style>` を書いて済ませない。CSS の行も本文の文字数（全角250字まで）に数えられ、部品もテーマに残らない。

### outcome（条件→結果）

```markdown
:::: {.columns}
::: {.column width="62%"}
| | 条件 | 基準 |
|---|---|---|
| ① | 項目別の読み誤り | 手入力 以下 |
:::
::: {.column width="6%"}
[→]{.arrow}
:::
::: {.column width="30%"}
::: {.outcome .accent}
3つすべて満たす

切り替える
:::
::: {.outcome}
1つでも満たさない

手入力を続ける
:::
:::
::::
```

- 満たさないときの扱いを必ず置く。片側だけでは、読み手は「満たさなかったら？」を質問するしかない。

### number（大きな数字）

```markdown
[手入力の誤り率（現行）]{.small .muted}

[`{python} f"{err:.1%}"`]{.big}

**[「保留」の上限]{.small .accent-2}**

[要確認]{.tbd .big}%
```

- 数字はコードで計算して埋める。取れていない数字は `[要確認]{.tbd}` で残し、1枚目に `::: {.undecided}` の一覧を置く（lint: tbd-without-list）。
- 2つまで。3つ以上なら `table` か `chart` にする。

### roles（体制）

```markdown
:::: {.columns .roles}
::: {.column width="31%"}
経理課

「保留」の確認　月 [要確認]{.tbd} 時間
:::
::: {.column width="31%"}
情報システム課

会計システムとの連携・切替
:::
::::
```

- 1行目は担当の名前だけ。2行目以降はその担当がやることを1〜2行。`timeline` の下に置くと、いつ誰が何をするかが1枚で読める。

### timeline / direction / chart（図）

```python
#| fig-alt: "移行の4段階の工程表。1か月目に試験導入、2か月目に並行運用、3か月目に本番切替と定常運用。"
#| fig-width: 12.4
#| fig-height: 2.5
figs.timeline([("試験導入", 0.0, 0.9), ("並行運用", 1.1, 0.8, figs.ORANGE),
               ("本番切替", 2.0, 0.5), ("定常運用", 2.55, 0.45)], ["1か月目", "2か月目", "3か月目"])
```

```python
#| fig-alt: "閾値と読み誤り・「保留」の関係を向きだけ示した模式図。…棒の長さは実測値ではない。"
#| fig-width: 7.2
#| fig-height: 3.1
figs.direction([("閾値を上げる", [("読み誤り ↓", 0.6), ("「保留」↑", 0.7, figs.ORANGE)]),
                ("閾値を下げる", [("読み誤り ↑", 0.8), ("「保留」↓", 0.3, figs.ORANGE)])])
```

```python
#| fig-alt: "形式ごとの件数。PDF で届く請求書が30件で最も多い。"
#| fig-width: 13.3
#| fig-height: 3.6
figs.bars(df["形式"], df["件数"], highlight="PDF", unit="件")
```

- 最初の図のセルの前に、`include: false` のセルで `import figs` と `figs.setup()` を1回書く（import の書き方は `figs.py` の先頭）。
- `direction` は実測値が無いときだけ使い、`[棒の長さは関係の向きを示す。実測値が入るまで比率は仮]{.small .muted}` を添える。実測値があれば `chart`。
- 色は青（主張）・橙（もう1つの群、注目させる段）・灰（強調しない）の3つまで。凡例を置かず、ラベルを棒の横に書く。
- 動く版（revealjs を映して話す枚だけ）: `figs.bars` の代わりに `parts.bars`（または ECharts の `parts.echart_bars`）、`[値]{.big}` の代わりに `parts.stat`。`#| output: asis` のセルで `print(...)`、引数は figs と同じで `alt=` が `fig-alt` の代わり、増減は `sign=True`。枚を開くたびに棒が伸び数字が数え上がる（theme/motion-gsap.html）。`render_check.sh` の全枚スクショと PDF、`?print-pdf`・`?static` では最終状態。pptx では文字だけになるので、pptx 主体のデッキでは使わない。構成バー `parts.stack`・人のアイコン `parts.pictos`・章バッジ `parts.badge`・吹き出し `parts.callout` も同じ流儀（`scripts/parts.py` の先頭に例）。
- 分岐・手順の図（型 `flow`）は `parts.flow("""…""")` に D2 で書く（`A: 文言`、`A -> B: はい`、結果は `{class: out}`、推す結果は `{class: go}`、注意は `{class: warn}`、縦に並べるなら先頭に `direction: down`）。色は `_brand.yml` から、枚を開くと線の順に描く。初回は `tools/d2` の npm ci と Noto Sans JP の取得が走る（node が要る）。Mermaid のセルもそのまま使える。
- 話しながら1段ずつ見せる: 段ごとに `<div class="fragment" data-ig-step="1">…</div>`（クリックで次の段、← で戻ると逆再生）。並び替えは `.ig-flip`（`data-ig-order` に並び替え後の id）と見えない合図 `<span class="fragment ig-trigger" data-ig-flip="#id"></span>`。台本は `::: notes`（S キーの発表者ビューに出る）。見本は `decks/2026-10-25-gsap-demo`・`decks/2026-10-25-abtest-oss`。

## 確認型だけの部品（design-doc スキル）

| 書き方 | 見た目 | 用途 |
|---|---|---|
| `::: {.check}` 本文 `:::` | 下端の帯。「確認点　」が青の太字で先頭に付く | 確認型の各枚に1つ |
| `::: {.undecided}` 段落1つ＝1項目 `:::` | 「まだ決めていない点」の見出しと点線の枠 | 1枚目の右の列（`.tbd` を使うデッキすべて） |

## 共通の部品

| 書き方 | 見た目 | 用途 |
|---|---|---|
| `[要確認]{.tbd}` | ［要確認］を灰の点線の枠で | 取れていない数字の位置 |
| `[注記]{.small .muted}` | 20pxの灰 | 図の但し書き |
| `[語]{.accent-2}` | 橙 | 2つ目の群の見出し |
| `[出典]{.source}` | 左下16pxの灰 | 出典・確認中の但し書き |
| `[92.9%]{.e1}` | 青の太字 | 文中の結論の数字・語（1枚に1か所まで） |
| `[語]{.e2}` | 橙の太字 | 文中の対比・注意の語 |
| `[語]{.e3}` | 黒の太字 | 文中の強調（色を足したくないとき） |

スタイル（`style="…"`）を本文に直接書かない。部品が足りなければ `theme/custom.scss` に足し、この表に加える（どのデッキも同じ見た目にするため）。
テーマに無いクラス（`{.e4}` など）は書いても見た目が変わらず素通りするので、lint が `class-undefined` で知らせる。
