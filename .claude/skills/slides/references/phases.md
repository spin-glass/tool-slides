# フェーズ1〜4の全文

`SKILL.md` から移した全文（2026-10-07）。`SKILL.md` には手順の骨と block の規則の要点だけを残した。数字・写真の枚数・標本（分母）・未確定の値の書き方、承認済みのタイトルを変えるときの手順、検証の細目は、ここのフェーズ3・4にある。

## フェーズ1: インタビュー（生成禁止ゲート）

次の3点が揃うまで、アウトラインもタイトル案も書かない。

1. **聴衆**: 誰か、その人が既に何を知っているか
2. **行動**: 読後・聴後に取ってほしい行動を1つ（承認する、選ぶ、使い始める、理解して質問しない、など）
3. **持ち時間**: 発表なら分、配布なら読了時間 → budget（本編枚数）を提案し合意する

- 質問は1回にまとめ、答えられない項目には選択肢を示す。推測で埋めて先へ進まない。
- 素材（数字・事実・決定事項）が足りず、一般論や言い訳でしか埋まらない箇所が出たら、文章で繕わず「何が足りないか」を本人に尋ねる。
- 合意したら `index.qmd` の YAML の直後に記録する:

```markdown
<!-- audience: 経理部長（月次決算の流れは熟知、MLは未経験） -->
<!-- action: 請求書OCRの試験導入を承認する -->
<!-- minutes: 10 -->
<!-- budget: 6 -->
<!-- status: ghost -->
```

**本人が任せた場合**（「自由に決めてよい」「任せる」と明示したとき）: 任された項目は尋ねずに自分で決める。
決めた範囲と本人の原文を `<!-- decided-by: claude（本人の委任「…」日付） -->` に記録する。
任されたのが3点と骨子の両方なら、フェーズ2の承認待ちも省いて進めてよい。その代わり、最終報告の冒頭で
決めた聴衆・行動・持ち時間とタイトル一覧を示し、本人がすぐ差し戻せるようにする。任されていない項目は尋ねる。

## フェーズ2: ゴーストデッキ承認

本文なしで、アクションタイトルだけの骨子を `index.qmd` に書き、本人に見せる。

- 各枚は `## アクションタイトル` と `<!-- evidence: 証拠予定を1行 -->` と `<!-- type: 型 -->` だけ。型は証拠の形から `references/slide_types.md` の「型の選び方」で1つ選ぶ（前→後なら `pair`、条件と扱いなら `outcome`、期間なら `timeline`、迷ったら `text`）。連読リストに「型:」として出るので、骨子と一緒に本人に見せる。
- アクションタイトル: 完全文、so-what（だから何か）、可能なら数字、全角40字以内、述語で終える。体言止めや「〜について」「まとめ」のようなラベルは使わない。
- 書いたら `python3 .claude/skills/slides/scripts/lint_slides.py --titles decks/<name>/index.qmd` の連読リストを本人に示す。
- 見せる前に自分でタイトルだけを上から読み、論旨が一本で通るか確かめる。通らない枚・重複する枚は削る。budget 内に収まらなければ、何を appendix へ送るかを提案する。
- 本人が承認するまで本文を書かない。承認されたら `status: approved` に書き換え、コミットする（lint は git の HEAD の承認済みの版と比べて、承認後の budget の書き換えを止め、タイトルの変更を知らせる）。
- **budget は本人と合意した約束。** 本文を書いていて枚数が足りなくなったら、budget の数字を書き換えず、appendix へ送るか、枚を足す案を本人に出して承認を取り直す。承認を得たら `<!-- reapproved: 本人「6枚でよい」 2026-10-05 -->` のように本人の原文と日付を書く（無いと lint が block する）。
- データから結論を出すデッキでは、タイトルに入る数字が出るまで骨子を確定できない。先に前処理と集計を済ませ、出た数字でタイトルを書く（数字を見る前に結論を決めない）。
- 本人に任された場合も、タイトル連読の自己確認は省かない。

## フェーズ3: 本文生成

- 各枚は骨子で選んだ型の書き方（`references/slide_types.md`）で書く。部品（`.pair`・`.outcome`・`.big`・`.roles`・`.tbd`）と図（`figs.*`）を使い、`style=` や色の値を本文・セルに直接書かない。型を変えたら `<!-- type: -->` も直す。
- 1枚＝承認済みタイトル1つの証明。タイトルを勝手に変えない（変えるならフェーズ2に戻って承認を取り直す）。例外は、タイトルの主張が写真やデータと食い違い、検査の手当て（`imgfig.claim` の `outside=`、`imgfig.measured`、数え直し）でも解消しないときだけ。そのときも、**編集する前に**変更案（元のタイトル・新しいタイトル・食い違いの根拠）を本人に出し、承認を得てから変える。事後の報告で済ませない。検査の warning を消すためにタイトルを言い換えない（手当てがあるのに文言を変えると、承認した主張が黙って変わる）。承認を得たら `<!-- reapproved: 本人「…」 YYYY-MM-DD -->` を書く。本人に任されている（`decided-by`）ときだけ、変えた理由を最終報告の冒頭に書いて進めてよい。
- bullets は目標3、上限5。1つの bullet は1行の事実か数字。
- **条件句を落として1行に収めない。** 収まらなければ、条件を見出しへ上げるか、2行に分ける。1行に詰めると最初に落ちるのが条件句（「〜の面では」「ただし」「〜の場合」）で、落とした瞬間に文の射程が原文より広がる。
- **`claim` に無い句を足さない。** 特に、断定を整えるための対の否定句（「A でよいので B にはしない」の B の側）を足さない。未決・想定の主張は、見出しでも未決・想定と分かる形にする。
- 各枚を書き終えたら、枚全体を発表者ノート（`::: {.notes}`）まで含めて読み返し、行どうしの矛盾（同じ枚に未決と確定が並ぶ、本文で取り下げた比較基準や数値がノートに残る）が無いかを確かめる。確定と書いた行の隣に、同じ事柄を未決とする行が並んだ例と、本文では外した比較基準の数値がノートに残った例があった。
- 出典のある主張を載せるデッキでは、YAML に `claims: required` を書き、`claims.csv` に出典の文（`quote`）と読んだときの版（`rev`）を写す。数字が無く決まった文字列も含まない言い換えは、lint・数値の照合・NG語のどれも通るので、表で出典と照らすしかない（design-doc/references/claims.md）。
- **claims.csv があるデッキは `claims: required` と同じに扱う**（YAML に書かなくても、lint は claims の無い本編の枚を block にする）。`claims-file`・`claims-source` の block と warning を「別のセッションが作った表だから対象外」と報告で片付けない。表の中身（特に note）を読み、自分の枚に関係する行を報告に書く。表の note がデッキの誤りを名指ししていたのに、block 99件を「他セッション由来」として一度も読まなかった例があった。
- **本編の各文を、その枚の claims の claim と quote に並べて1文ずつ読む。** 限定句の脱落・原文に無い句は、書いた時点でここで止める（レビューの観点にもあるが、書く側の手順に入れる。後から見つかった5件は書いた時点で防げた）。報告には lint の「見た範囲」に加えて「照らした文N／照らせなかった文K」を書く。
- **原文と違う語をデックで使うときは、claims.csv の `terms` 列に「デックの語=原文の語」を書く**（同じなら「同じ」）。列があれば、target が deck・both の行の空欄を warning にする。原文に無い語（設計書に無い略語や言い換え）を作らない。設計書の語（範囲外・線引き・版のような、設計書の中でだけ通じる語）をそのまま聴衆に出していないかは、lint が出す「設計書の語をそのまま使った箇所」の一覧を人が見る（語が毎回変わるので辞書にしない）。
- 話す文（前置き・つなぎ・補足説明）はスライドに書かず `::: {.notes}` に入れる。
- 本編の物語に不要な素材は `<!-- appendix -->` の後ろへ。appendix は budget と密度制限の対象外。appendix のスライドには、タイトルの上に「付録」と自動で出る（出ないと、聴衆には本編が結論の後も続くように見える）。
- **判断の根拠を付録へ逃がさない。** 本編の字数・箇条書きの上限に当たったとき、図や実例を付録へ送るのは最も楽な手だが、判断を仰ぐ枚から根拠が消える。減らすのは文で、図は残す。行動が「選ぶ・判断する」のデッキで、最後の枚（行動を頼む枚）に図も表も無いと lint が warning を出す。
- 本編の最後の枚は、聴衆にしてほしい行動（`action`）をタイトルに書いて終える。依頼の言葉をノートに回さない。
- **複数の枚で使う読み込み（`load_table`・`load_look`・共通の関数）は、最初の `##` より前の `include: false` のセルに置く。** 後ろの枚のセルで定義すると、前の枚に図を足したときに `NameError` で描画が止まる（セルは上から順に実行される）。
- 数値・表・グラフはコードセル（`{python}`）で計算・描画し、手で写さない。データは同じフォルダに置く。写真の図を使うデッキでは、本文・箇条書き・出典行の枚数を `{python} len(...)` で埋める（手で書くなら、描画のコードに assert で検算を書く）。分け直した後に古い数が残るのを防ぐため、lint が block する。
- タイトルは見出しなのでコードで埋められない。タイトルに書いた数字は、最初のスライドの `include: false` セルで `assert` して検算する（データが変わったら描画が止まる）。写真の図を使うデッキで、タイトルが写真の集合に当たらない測った枚数（人手で数え直した件数など）を言うときは、`imgfig.measured("タイトルの文", {数: 計算した値, …})` で確かめる（値が合わなければ止まり、render_check の「確かめていない」の warning も消える。値には文字列ではなく計算した数を渡す）。数値一覧（設計書の数の表など）で検算済みの、写真に当たらない数のタイトル（「1200枚で読み誤りが48枚から30枚」など）は、その枚に `<!-- counts: checked plans/numbers.md で検算 -->` のように何で確かめたかを書くと、render_check の「確かめていない」から外れる（理由が空だと外れない）。タイトルが写真の枚数を言うときは、そのスライドのコードセル（`include: false` でよい）で `imgfig.claim("タイトルの文", {数: その数の写真, …})` を呼ぶ。数ごとに、文が指す範囲（「〜のうち」「〜が写る」「〜の写真」）の写真を確認の表から選び直して渡す（図や前の計算の一部を流用しない）。例: `imgfig.claim("ラベルが犬の誤り12枚のうち7枚は、猫かオウムの写真だ", {12: dog_wrong, 7: [it for it in dog_wrong if imgfig.present(it, "猫") or imgfig.present(it, "オウム")]})`。数が合わなければ描画が止まる。render_check は、claim の無いタイトルの枚数と、文の名前（クラス）が写っていない写真、「12枚のうち7枚」の7枚に入れなかった写真にも名前が写るときを知らせる（文の形容で外した写真、たとえば「黒い猫」の文で外した白い猫は `outside=` に渡す）。
- **1つのデッキで標本（分母）が2つ以上あるとき**（全体の写真・人手で数え直した写真・評価用の写真など）は、数字のある本編の各枚の見出しの末尾に `{denominator="人手で分類し直した写真"}` と書き、その枚の数字が何の集まりから数えたものかを宣言する（画面には出ない）。1枚でも宣言すると、宣言の無い数字の枚（`{python}` の埋め込みを含む。日付と出典行は除く）を lint が知らせる。`--titles` の連読リストに「標本:」として出るので、骨子の承認でも確かめる。
- **1つの列・1つの語に、別の指標を混ぜない。** 区分ごとの割合は、「正解の側から見た割合」（本当は A の請求書のうち A と判定できた割合＝recall）か「判定の側から見た割合」（A と判定したうち本当に A だった割合＝precision）かを列名に書く。「正解率」は全体の Accuracy にだけ使う。区分ごとの表で、各行が recall、合計の行が Accuracy なのに同じ「正解率」の列に並び、聴衆も作者も区別できなかった例があった。
- **標本がどれかのモデルの判定で層を分けて抜いてあるとき**（現行モデルが A と判定した層・B と判定した層から決まった数ずつ抜くなど）は、区分ごとの recall がそのモデルに有利に出る（正解が A の請求書の大半が、そのモデルが A と判定した層から来るため）。recall を出すならその偏りを注記し、主には判定の側から見た割合（層ごとの precision。この偏りがかからない）を使う。
- 確かめられない値は `[要確認]` と書き、推測で埋めない（lint が block するので、本人に確認する流れになる）。聴衆に「まだ決めていない値」として見せる場合だけ `[要確認]{.tbd}`（灰の点線の枠）にし、1枚目に `::: {.undecided}` の一覧を置く（`design-doc` の確認型）。
- 本文を書く前に `references/style_guide.md` と `references/examples_ja.md` を読む。

## フェーズ4: 検証

1. `python3 .claude/skills/slides/scripts/lint_slides.py decks/<name>/index.qmd`（tool-slides の外なら `python3 ~/.claude/skills/slides/scripts/lint_slides.py <デッキ>/index.qmd`）を自分で走らせ、block を 0 にする。Stop hook の有無にかかわらず走らせる（hook は Claude Code だけ。`references/agents.md`）。
   **報告には、検査ごとに見た範囲を書く。「block 0」だけを書かない。** lint は最後に「見た範囲: 本編 N枚／claims のある枚 M枚／claims の無い枚の文 K文」を出す。K文は出典と照らしていないので、そのまま報告に写す（NG語0件・数値の未照合0件とだけ書いた報告で、本文の平叙文を出典と照らしたものが0文だったことがあった）。
2. 直すのは違反したスライドだけ（Edit で該当箇所を置換）。デッキ全体を再生成しない。
3. 写真を並べたスライドは、主張（タイトル・箇条書き・見出し・画像ごとの説明）ごとに、該当する画像を `imgfig.py sheet`（元の写真があればそれ）で見て、主張と合うかを1件ずつ確かめる。とくに「〜だけ」「どれでもない」「ラベルの誤り」の画像は、元の写真を1枚ずつ開く。スクショの縮小画像で済ませない。
4. `.claude/skills/slides/scripts/render_check.sh decks/<name>`（tool-slides の外なら `~/.claude/skills/slides/scripts/render_check.sh <デッキ>`）で全枚を PNG にし、全枚を Read で目視する。写真の図があれば、図の説明と群の見出しを確認の表（`data/look.csv`）と照らした食い違い、拡大で確かめていない写真、ラベルの数を写真の中身として書いた文、`imgfig.claim`・`imgfig.measured` で確かめていないタイトルの枚数、claim の文と写真の食い違い、確認の表に無い写真、本文が下端を越える枚・出典行や確認点の帯に重なる枚が WARNING で出るので、0件にする（0にできない検査は無視されるようになるので、件数が増えたら必ず原因を見る）。はみ出し・折り返し崩れ・フォント崩れ・読めない図を探し、見つけたら該当スライドだけ直す。画像を並べた図は、スライド上での1枚の大きさの目安が図ごとに表示される。「小さい」と出た図は、見せる枚数を減らすか、図を分ける。図の合計サイズと1MB超の図も表示される。
5. 最後に `quarto render decks/<name>/index.qmd`（必要なら `--to pptx`／`--to beamer`）で出力する。PDF が要るときは `render_check.sh <デッキ> --pdf` で、検収した PNG を1枚1ページに綴じた `<デッキ>/<フォルダ名>.pdf` を作る（文字は選択できないが、画面と同じ見た目・同じ枚数になる。revealjs の `?print-pdf` は縦長の枚を2ページに分け、6枚が8ページになる）。tool-slides の外のデッキは render_check.sh が出した HTML がそのまま成果物になる。公開まで頼まれているときは tool-slides の `scripts/publish.sh`（公開するのは tool-slides の中のデッキだけ）。
6. **検査を段階に分ける。** 編集ごとには描画しない検査（`lint_slides.py`、`claims.py`、写真の数の検算。数秒）だけを走らせる。図やレイアウトを変えたときに `render_check.sh` で描く。区切り（本人に見せる前・完成と言う前）には、全枚の目視と出典との照合をサブエージェントに任せる（自分で書いた枚は自分で見ても見落とす）。
7. **報告の規律。** 「編集した」と報告する前に、`grep` か `git diff` で反映を確かめる（言っただけで編集していなかった例があった）。検査の結果には、その検査が見ないものを併記する（「数値の照合は数字しか見ない」「lint は文の意味を見ない」「claim の照合は claims のある枚だけ」）。結果を「裏取りした」と読める形で書かない。
8. ターン終了時に Stop hook が同じ lint を走らせる。block されたら理由に書かれた枚だけを直す。
9. lint や図の関数を直したら、tool-slides で `.venv/bin/python -m unittest discover -s tests` を通す。
