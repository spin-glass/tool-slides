# 具体例の画像で説明する（手順）

`SKILL.md` フェーズ3 から移した手順の全文。写真を並べるデッキでは、本文を書く前に読む。理由つきの規約は `style_guide.md` の「具体例の画像で説明する」。

型は1つ:「数の主張を、その数の中身の画像で見せる」。タイトルに枚数を書き、図にその枚数の画像を並べ、見て分かった事実を書く。
閾値の移動も、誤分類も、変更の前後も、切り口が違うだけで作り方は同じ。図は `scripts/imgfig.py` で描く。

1. **表を読む**: 1行＝1画像（`id` と、切り口に使う列）。画像は `thumbs/<id>.jpg`。`imgfig.load_table` で読み、列は `it["列名"]` で使う。
2. **切り口を1つ決めて群に分ける**（下の表）: `imgfig.split_by`、2軸なら `cross`。群の枚数がタイトルの数字になる。
3. **並べ方を選ぶ**: 図の関数は図を返さない（セルの最後に `;` を付け忘れても、同じ図が2つ出ない）。図のファイルが要るときだけ `return_fig=True` で受け取る。1群は `grid_figure`（何の例かは `title="猫と判定した写真"` で見出しにする。`counts=True` で「N枚」も付く）。2〜3群の対比は `panels_figure`。小さい群がたくさんあるとき（誤りの組ごと、など）は `flow_figure`。「1枚とその相手」は `rows_figure`。2軸の小さな表は `matrix_figure`。数値の軸に沿うなら `histogram_figure`。列数は省けば、1枚が最も大きくなるように決まる。
4. **見せる画像は全数か、規則で選ぶ**: `pick(items, k, how="even" | "top" | "bottom" | "random")`。選び方を `pick_note` で `{.source}` に書く（書かないと lint が warning を出す）。
5. **1つの図は12〜16枚まで**にして、1枚をスライド上で150px以上にする。全数がそれより多いときは、最も多い群を1枚で大きく見せ、残りはスライドを分けるか、規則で選んで全数を appendix に置く。30枚を1つの図に詰めると1枚が約85pxになり、何が写っているかが読めない。
6. **何が写っているかを言い切る**（被写体・場所・写り方。例:「見逃した8枚は、端に小さな傷がある部品だ」）。見た目の特徴を並べるだけでは、何の画像かが伝わらない。少数を大きく見せる図では、画像ごとにも一言添える（`caption` の2行目。例:「傷あり→傷なし 0.92\n端の小さな傷」）。説明が枠の幅（全角約6字）より長いと、図の関数が「＋・、」の後ろか「（」の前で折り返す（呼び出し側で `replace("＋", "\n")` しなくてよい）。画像ごとの説明は確認の表から作る: `items = imgfig.load_look(items, "data/look.csv")` として、説明の1行目を `imgfig.seen(it)`（`classes` をすべてつなぎ、`note` を括弧で添えたもの。例「猫（主役はオウム）」）にし、2行目にデータ（ラベル・予測・確信度）を置く: `caption=lambda it: f"{imgfig.seen(it)}\n{it['pred_ja']} {it.num('prob'):.2f}"`。主役だけの短い名前の列を別に作って説明に使わない（写っている対象を落とす）。同じ画像を複数の図に載せるときも同じ説明にする。箇条書き・ノートで写真の中身（何が写るか、種の名前）を言うときも、確認の表の言葉を使い、表に無い名前を足さない。群の見出しで写っている対象を言うとき（「写真は猫」）は、`classes` がそれ1つの画像だけを入れ、2つ以上写る画像は「両方写る」などの群に分ける。撮影者の題名などの裏付けがあれば使い、目視で付けたならそう書いて、付けた表を `data/` に残す。なぜ間違えたかの推測は本文に書かず、ノートに推測と断って書く。
7. **画像について書く前に、元の写真で1枚ずつ見る**: 図に並べた縮小画像やスライドのスクショでは、小さく写るもの（車の中の動物、遠くの群れ、別の動物の陰にいる動物）やよく似た種を見分けられない。見せる画像を `imgfig.py sheet`（または `imgfig.review_sheet`）で ID・データ・撮影者の題名つきで並べ、Read で開いて確かめてから書く。群を足したり見せる写真を入れ替えたりしたら、増えた写真を同じ手順で見て確認の表に足す（表に無い写真は説明が空になり、render_check が「確認の表に無い写真」として知らせる）。確かめた結果は **確認の表 `data/look.csv`**（`id, label_class, classes, unsure, note, closeup`）に1枚1行で書く。`label_class` はデータのラベルのクラス（スライドに書く名前で）。`unsure` は、写っているかを写真から決めきれない分類の対象（遠くの影・ぼけた姿など。例 `犬`）。`classes` は元の写真に写っている分類の対象（クラス）をすべて、スライドに書く名前で「;」区切り（例 `犬;猫`）。`note` は分類の対象以外で目立つもの（主役が分類の対象でなければ主役）を10字程度で（例 `主役はオウム`）。データに元の写真（縮小画像より大きい `images/` など）があれば、`sheet` はそれを長辺480pxで並べる。主役だけでなく、端・奥・物の陰・空まで見て、**写っている分類の対象（クラス）をすべて**書く（例:「犬。奥のソファに猫もいる」）。主役しか書かないと「どのクラスでもない」「〜だけ」と同じ誤りになる。**分類の対象が1つも写っていない（`classes` が空）か、ラベルのクラスが写っていない（`label_class` が `classes` に無い）とした写真は、`imgfig.py closeup --look data/look.csv --thumbs data/thumbs --classes <クラスをカンマ区切り> --out _check/closeup` で写真全体と4つの区画の拡大を並べた画像を作り、1枚ずつ Read で開いて区画ごとに探し直す**（大きな別の物の後ろ、体や翼の陰、遠く・端に写る対象を落としやすい）。確かめたら `closeup` 列に yes と書き、見つけた対象は `classes` に足す（render_check が、拡大で確かめていない写真を知らせる）。名前は、見た目で誰でも言える一般的な名前（犬、オウム、車）までにする。クラスより細かい名前（種・品種・型番）は見た目から当てず、撮影者の題名などデータにある名前を、元の表記のまま出どころを添えて書く（例 `Border Terrier（題名）`）。訳さない（訳すと、似た名前の別の種と取り違えやすい）。データに無ければ、クラス名と見た目で書く（例 `白い大型の犬`）。「写っていない」「〜だけ」「どれでもない」「ばかり」「1枚も」と書く画像は、元の写真を1枚ずつ Read で開いて探し、1枚も外れないときだけ書く（lint が `image-absolute` で知らせる）。小さすぎて決められないときは、決められないと書き、そのクラスを `unsure` に入れる。**「写っていない」「〜以外」と数えるときは `imgfig.absent(it, クラス)` で数え、決めきれない写真は「決めきれない」として別に数える**（タイトル・箇条書きの枚数にも入れない）。説明（`imgfig.seen`）には決めきれない対象が「犬?」と出る。説明・`note` には写真で見えることだけを書き、種の知識で補わない（写っていない牙・角・鳴き声・行き先などを書かない）。
8. **データのラベルも疑う**: 人手で付けた正解ラベルにも誤りがある。元の写真で見て、ラベル（や撮影者の題名）と写っているものが合わない画像は、黙ってラベルどおりに扱わない。誤りの分析では「ラベルの誤り」と「モデルの誤り」を分けて数える。「ラベルの誤り」とするのは、ラベルのクラスが写真のどこにも写っていないことを元の写真で確かめたときだけ。ラベルのクラスと予測のクラスが両方写っていれば「両方写る」として別に数える（どちらの誤りでもない）。混同行列など数だけのスライドでも、ラベルで数えた枚数を「犬の写真」「犬が写る」と書かない。ラベルの数は「ラベルが犬の写真」と書き、写っている数は確認の表で数える（render_check が、ラベルの数と同じで確認の表の数と違う「N枚は犬の写真」を知らせる）。表示するラベルを直すときは `data/label_fix.csv`（id, 直したラベル, 理由）に残して付録に書き、タイトルの数字が変わらないかを確かめる。
9. **小さく写る対象は、拡大して見せる**: 主張に関わる対象が写真の一部に小さく写る（端・奥・物の陰）ときは、`imgfig.zoom_figure` で写真全体（枠つき）と、元の写真から切り出した拡大を並べる。縮小画像のままでは聴衆に見えない。枠は `imgfig.py locate` の目盛りつき画像で位置を読んで決め、描いた図を Read で開いて、枠の中に対象が入っていることを確かめる。

| 切り口 | 群の作り方 | タイトルの例 |
|---|---|---|
| 閾値の移動 | 2本の線の間にいる画像 × 正解（`moved`・`moved_figure`） | 線を1%から5%へ動かすと、犬6枚を失って犬以外40枚を除ける |
| 正解×予測 | 誤った画像を（正解, 予測）で `split_by` | 傷ありを見逃した8枚は、すべて端の小さな傷だ |
| 変更の前後 | 前後で結果が違う画像を（前, 後）で `split_by` | 新しいモデルで12枚が直り、3枚が新たに誤りになる |
| スコアの順 | 上位・境界・下位を `pick` | 確信度が最も低い20枚の半分は、暗い写真だ |
| 群ごとの代表 | 型・クラスタ・期間で `split_by` し、各群から `pick` | 投稿写真は5つの型に分かれ、最多は店内の写真だ |
| 基準の両側 | 該当・非該当・迷う例を並べる | 「対象外」にするのは、店の文脈が写っていない写真だ |
| 似たもの | 1枚と、その近傍や典型例（`rows_figure` の見出しを Item にする） | 見逃した傷は、汚れの写真に最も近い |

表にない切り口でも手順は同じ: 群を作る → 枚数を数える → 並べる → 選び方を書く。
誤りや変化を数えるときは、正解ラベルのほうが違う画像が混じっていないかを画像で確かめ、混じっていれば分けて数える。

- 重い処理（ダウンロード・埋め込み計算・推論）はデッキのフォルダの `prepare.py` に分け、結果の表とサムネイル（`data/`）をコミットする。qmd は結果を読むだけにして、描画に重い依存を持ち込まない。実行は `uv run --no-project --with … python prepare.py`。
- 第三者の画像は、ライセンスと作者を記録し（`data/credits.csv`）、作者・出典の一覧（`credits.html`）を YAML の `resources:` でデッキと一緒に公開する。公開するデッキでは、顔の分かる人物・読めるナンバープレートなどが写る画像を目視で外し、外した画像と理由を `exclude.csv` に残す。
- 他人のデータでモデルを動かす前に、そのデータの決まり（事前登録・評価用データの隔離など）を確かめる。決まりに触れるなら、別の独立したデータで作る。
- 規約と理由は `references/style_guide.md` の「具体例の画像で説明する」、見本は `decks/2026-09-30-outlier-threshold-images/`（閾値の移動）。
