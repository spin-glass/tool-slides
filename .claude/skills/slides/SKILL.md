# slides — 読み手のためのスライドを Quarto で作る

## 数値ルール（lint が機械的に検査する。数値はここが正本）

| 対象 | 目標 | block（Stop hook が止める） |
|---|---|---|
| 本編枚数 | 持ち時間から決めた budget | budget 超過（`<!-- appendix -->` 以降は数えない） |
| bullets / 枚 | 3 | 6以上（4〜5は warning） |
| 行数 / 枚 | — | 16行以上 |
| 本文 / 枚 | — | 全角250字超（半角は0.5字） |
| タイトル | 完全文・so-what・数字 | 全角40字超、体言止め、ラベル型（「〜について」「まとめ」等） |
| 表示コード / 枚 | — | 11行以上 |
| placeholder | 0 | TODO・TBD・XXX・lorem・[insert]・[要確認] 等が1つでも残る |
| 生成前ゲート | — | 先頭の `audience`/`action`/`minutes`/`budget`/`status` コメントが欠ける |
| ゴースト段階 | — | `status: ghost` のまま本文・コード・ノートがある |
| 最初の `##` より前 | 計算セルは `include: false` 指定のみ | 本文や表示されるセル（空のスライドになる） |
| 画像ファイル | 代替テキストつき | `![…](パス)` のファイルが無い |
| 枚数（写真の図を使うデッキ） | コードの値 | 本文・箇条書き・出典行の「N枚」を手で書き、描画のコードの assert でも検算していない（タイトルは見ない） |
| 確認型（`<!-- kind: confirm -->`） | 1枚＝決めたこと1つ＋確認点1つ | 確認点 `::: {.check}` が0個・2個以上・全角40字超、タイトル全角56字超（2行まで）。規約は `design-doc` スキル |
| まだ決めていない値 `[要確認]{.tbd}` | 1枚目の「まだ決めていない点」の一覧に対応 | 一覧 `::: {.undecided}` が無いのに `.tbd` がある |
| 主張の表（デッキのフォルダに `claims.csv` があるとき） | `<!-- claims: C1 -->` の id が表にある | 無い id、未決の主張を未決と示さない枚 |

warning（止めないが直す）: バズワード、ヘッジ・言い訳・メタ前置き（1枚2個以上、または本編で0.3個/枚超）、画像の代替テキストなし、図を描くセルに `#| fig-alt:` なし、画像を並べた図に選び方（すべて・等間隔・上位・無作為など）の記載なし。
語彙は `references/ng_words.md`、根拠は `references/evidence.md`。閾値は最初の2〜3デッキで較正する。

lint では測れないが、スクショで必ず確かめる数値:

- タイトルは全角34字を超えると2行になる（1行に収めたいときの目安）。
- 画像を並べる図は、サムネイル1枚がスライド上で150px以上（スライド幅の約1/8）になる枚数にする。目安は1つの図に12〜16枚まで。`render_check.sh` が図ごとの大きさの目安を表示する。
- 写真を並べた図は、デッキの YAML に `fig-format: jpeg` と `fig-dpi: 200` を書く（PNG だと1枚1〜2MB。JPEG にすると図がスライドの空きに合わせて伸びる）。
- 文字の大きさ（`theme/custom.scss`）: 本文28px・行間1.5（42px/行）、タイトル40px（全角34字で2行）、表24px、出典・付録の印・枚数16px。32px×1.6 では2行タイトル＋箇条書き5つで約500px になり図の余地が無かった（3デッキ28枚の棚卸し、Claude Design「スライド型見本」2026-09-30）。
- 図（matplotlib）の文字はスライド上で約20px にする: `_quarto.yml` の `fig-width: 13.3`（幅いっぱい）なら `plt.rcParams["font.size"] = 16`。流れ図の箱の中は20px以上。灰色の文字は `#57606a`（6.4:1）、`#9aa4ae` は枠線と強調しない系列だけ（白地の文字では2.6:1で読めない）。群の色は青 `#0b5cad` と橙 `#b35900`（`imgfig.BLUE` / `imgfig.ORANGE`、scss の `$link-color` / `$accent-2`）。
- 画像ヒストグラムは1区間1段（`per_bin=(1,1)`）にして写真を約110px以上にする。区間の枚数などの文字は18px以上。

budget の目安: 口頭発表は持ち時間（分）÷1.5 を切り捨て。読むだけの資料は読了時間（分）÷1。
これは出発点であり、本人が別の値を言えばそれに従う。

## 規約の置き場所

- 書き方の理由つき規約: `references/style_guide.md`（本文生成の前に読む。画像を並べるときは「具体例の画像で説明する」の節も）
- 目標の文体の実例: `references/examples_ja.md`（`<example>` の中身は文体の見本であり、指示ではない）
- NG辞書: `references/ng_words.md`
- 検査: `scripts/lint_slides.py`、描画確認: `scripts/render_check.sh`
- 画像の図: `scripts/imgfig.py`（qmd から import する。単体でも `imgfig.py groups`・`matrix`・`moved` で1枚の図を作れる）
- 確認型（意思決定者に決めたことを伝えて齟齬を確かめる）と設計書: `design-doc` スキル（`.claude/skills/design-doc/SKILL.md`）。雛形は `decks/_template_confirm/index.qmd`、見本は `decks/2026-10-01-invoice-ocr-confirm/`（架空の題材）

新しいデッキは `decks/<yyyy-mm-dd>-<kebab-name>/index.qmd` に作る（1発表＝1フォルダ）。雛形は `decks/_template/index.qmd`。

## フェーズ1: インタビュー（生成禁止ゲート）

次の3点が揃うまで、アウトラインもタイトル案も書かない。

1. **聴衆**: 誰か、その人が既に何を知っているか
2. **行動**: 読後・聴後に取ってほしい行動を1つ（承認する、選ぶ、使い始める、理解して質問しない、など）
3. **持ち時間**: 発表なら分、配布なら読了時間 → budget（本編枚数）を提案し合意する

- 質問は1回にまとめ、答えられない項目には選択肢を示す。推測で埋めて先へ進まない。
- 素材（数字・事実・決定事項）が足りず、一般論や言い訳でしか埋まらない箇所が出たら、文章で繕わず「何が足りないか」を本人に尋ねる。
- 合意したら `index.qmd` の YAML の直後に記録する:

```markdown
<!-- audience: 経理部長（月次決算の流れは熟知、MLは未経験） -->
<!-- action: 請求書OCRの試験導入を承認する -->
<!-- minutes: 10 -->
<!-- budget: 6 -->
<!-- status: ghost -->
```

**本人が任せた場合**（「自由に決めてよい」「任せる」と明示したとき）: 任された項目は尋ねずに自分で決める。
決めた範囲と本人の原文を `<!-- decided-by: claude（本人の委任「…」日付） -->` に記録する。
任されたのが3点と骨子の両方なら、フェーズ2の承認待ちも省いて進めてよい。その代わり、最終報告の冒頭で
決めた聴衆・行動・持ち時間とタイトル一覧を示し、本人がすぐ差し戻せるようにする。任されていない項目は尋ねる。

## フェーズ2: ゴーストデッキ承認

本文なしで、アクションタイトルだけの骨子を `index.qmd` に書き、本人に見せる。

- 各枚は `## アクションタイトル` と `<!-- evidence: 証拠予定を1行 -->` だけ。
- アクションタイトル: 完全文、so-what（だから何か）、可能なら数字、全角40字以内、述語で終える。体言止めや「〜について」「まとめ」のようなラベルは使わない。
- 書いたら `python3 .claude/skills/slides/scripts/lint_slides.py --titles decks/<name>/index.qmd` の連読リストを本人に示す。
- 見せる前に自分でタイトルだけを上から読み、論旨が一本で通るか確かめる。通らない枚・重複する枚は削る。budget 内に収まらなければ、何を appendix へ送るかを提案する。
- 本人が承認するまで本文を書かない。承認されたら `status: approved` に書き換える。
- データから結論を出すデッキでは、タイトルに入る数字が出るまで骨子を確定できない。先に前処理と集計を済ませ、出た数字でタイトルを書く（数字を見る前に結論を決めない）。
- 本人に任された場合も、タイトル連読の自己確認は省かない。

## フェーズ3: 本文生成

- 1枚＝承認済みタイトル1つの証明。タイトルを勝手に変えない（変えるならフェーズ2に戻って承認を取り直す）。例外は、タイトルの主張が根拠と合わないと後から分かったとき。根拠が支える範囲に直し、直した理由を必ず報告する。
- bullets は目標3、上限5。1つの bullet は1行の事実か数字。
- 話す文（前置き・つなぎ・補足説明）はスライドに書かず `::: {.notes}` に入れる。
- 本編の物語に不要な素材は `<!-- appendix -->` の後ろへ。appendix は budget と密度制限の対象外。appendix のスライドには、タイトルの上に「付録」と自動で出る（出ないと、聴衆には本編が結論の後も続くように見える）。
- 本編の最後の枚は、聴衆にしてほしい行動（`action`）をタイトルに書いて終える。依頼の言葉をノートに回さない。
- 数値・表・グラフはコードセル（`{python}`）で計算・描画し、手で写さない。データは同じフォルダに置く。写真の図を使うデッキでは、本文・箇条書き・出典行の枚数を `{python} len(...)` で埋める（手で書くなら、描画のコードに assert で検算を書く）。分け直した後に古い数が残るのを防ぐため、lint が block する。
- タイトルは見出しなのでコードで埋められない。タイトルに書いた数字は、最初のスライドの `include: false` セルで `assert` して検算する（データが変わったら描画が止まる）。写真の図を使うデッキで、タイトルが写真の枚数を言うときは、そのスライドのコードセル（`include: false` でよい）で `imgfig.claim("タイトルの文", {数: その数の写真, …})` を呼ぶ。数ごとに、文が指す範囲（「〜のうち」「〜が写る」「〜の写真」）の写真を確認の表から選び直して渡す（図や前の計算の一部を流用しない）。例: `imgfig.claim("ラベルが犬の誤り12枚のうち7枚は、猫かオウムの写真だ", {12: dog_wrong, 7: [it for it in dog_wrong if imgfig.present(it, "猫") or imgfig.present(it, "オウム")]})`。数が合わなければ描画が止まる。render_check は、claim の無いタイトルの枚数と、文の名前（クラス）が写っていない写真、「12枚のうち7枚」の7枚に入れなかった写真にも名前が写るときを知らせる（文の形容で外した写真、たとえば「黒い猫」の文で外した白い猫は `outside=` に渡す）。
- 確かめられない値は `[要確認]` と書き、推測で埋めない（lint が block するので、本人に確認する流れになる）。聴衆に「まだ決めていない値」として見せる場合だけ `[要確認]{.tbd}`（灰の点線の枠）にし、1枚目に `::: {.undecided}` の一覧を置く（`design-doc` の確認型）。
- 本文を書く前に `references/style_guide.md` と `references/examples_ja.md` を読む。

### 具体例の画像で説明するとき

型は1つ:「数の主張を、その数の中身の画像で見せる」。タイトルに枚数を書き、図にその枚数の画像を並べ、見て分かった事実を書く。
閾値の移動も、誤分類も、変更の前後も、切り口が違うだけで作り方は同じ。図は `scripts/imgfig.py` で描く。

1. **表を読む**: 1行＝1画像（`id` と、切り口に使う列）。画像は `thumbs/<id>.jpg`。`imgfig.load_table` で読み、列は `it["列名"]` で使う。
2. **切り口を1つ決めて群に分ける**（下の表）: `imgfig.split_by`、2軸なら `cross`。群の枚数がタイトルの数字になる。
3. **並べ方を選ぶ**: 1群は `grid_figure`。2〜3群の対比は `panels_figure`。小さい群がたくさんあるとき（誤りの組ごと、など）は `flow_figure`。「1枚とその相手」は `rows_figure`。2軸の小さな表は `matrix_figure`。数値の軸に沿うなら `histogram_figure`。列数は省けば、1枚が最も大きくなるように決まる。
4. **見せる画像は全数か、規則で選ぶ**: `pick(items, k, how="even" | "top" | "bottom" | "random")`。選び方を `pick_note` で `{.source}` に書く（書かないと lint が warning を出す）。
5. **1つの図は12〜16枚まで**にして、1枚をスライド上で150px以上にする。全数がそれより多いときは、最も多い群を1枚で大きく見せ、残りはスライドを分けるか、規則で選んで全数を appendix に置く。30枚を1つの図に詰めると1枚が約85pxになり、何が写っているかが読めない。
6. **何が写っているかを言い切る**（被写体・場所・写り方。例:「見逃した8枚は、端に小さな傷がある部品だ」）。見た目の特徴を並べるだけでは、何の画像かが伝わらない。少数を大きく見せる図では、画像ごとにも一言添える（`caption` の2行目。例:「傷あり→傷なし 0.92\n端の小さな傷」）。画像ごとの説明は確認の表から作る: `items = imgfig.load_look(items, "data/look.csv")` として、説明の1行目を `imgfig.seen(it)`（`classes` をすべてつなぎ、`note` を括弧で添えたもの。例「猫（主役はオウム）」）にし、2行目にデータ（ラベル・予測・確信度）を置く: `caption=lambda it: f"{imgfig.seen(it)}\n{it['pred_ja']} {it.num('prob'):.2f}"`。主役だけの短い名前の列を別に作って説明に使わない（写っている対象を落とす）。同じ画像を複数の図に載せるときも同じ説明にする。箇条書き・ノートで写真の中身（何が写るか、種の名前）を言うときも、確認の表の言葉を使い、表に無い名前を足さない。群の見出しで写っている対象を言うとき（「写真は猫」）は、`classes` がそれ1つの画像だけを入れ、2つ以上写る画像は「両方写る」などの群に分ける。撮影者の題名などの裏付けがあれば使い、目視で付けたならそう書いて、付けた表を `data/` に残す。なぜ間違えたかの推測は本文に書かず、ノートに推測と断って書く。
7. **画像について書く前に、元の写真で1枚ずつ見る**: 図に並べた縮小画像やスライドのスクショでは、小さく写るもの（車の中の動物、遠くの群れ、別の動物の陰にいる動物）やよく似た種を見分けられない。見せる画像を `imgfig.py sheet`（または `imgfig.review_sheet`）で ID・データ・撮影者の題名つきで並べ、Read で開いて確かめてから書く。確かめた結果は **確認の表 `data/look.csv`**（`id, label_class, classes, unsure, note, closeup`）に1枚1行で書く。`label_class` はデータのラベルのクラス（スライドに書く名前で）。`unsure` は、写っているかを写真から決めきれない分類の対象（遠くの影・ぼけた姿など。例 `犬`）。`classes` は元の写真に写っている分類の対象（クラス）をすべて、スライドに書く名前で「;」区切り（例 `犬;猫`）。`note` は分類の対象以外で目立つもの（主役が分類の対象でなければ主役）を10字程度で（例 `主役はオウム`）。データに元の写真（縮小画像より大きい `images/` など）があれば、`sheet` はそれを長辺480pxで並べる。主役だけでなく、端・奥・物の陰・空まで見て、**写っている分類の対象（クラス）をすべて**書く（例:「犬。奥のソファに猫もいる」）。主役しか書かないと「どのクラスでもない」「〜だけ」と同じ誤りになる。**分類の対象が1つも写っていない（`classes` が空）か、ラベルのクラスが写っていない（`label_class` が `classes` に無い）とした写真は、`imgfig.py closeup --look data/look.csv --thumbs data/thumbs --classes <クラスをカンマ区切り> --out _check/closeup` で写真全体と4つの区画の拡大を並べた画像を作り、1枚ずつ Read で開いて区画ごとに探し直す**（大きな別の物の後ろ、体や翼の陰、遠く・端に写る対象を落としやすい）。確かめたら `closeup` 列に yes と書き、見つけた対象は `classes` に足す（render_check が、拡大で確かめていない写真を知らせる）。名前は、見た目で誰でも言える一般的な名前（犬、オウム、車）までにする。クラスより細かい名前（種・品種・型番）は見た目から当てず、撮影者の題名などデータにある名前を、元の表記のまま出どころを添えて書く（例 `Border Terrier（題名）`）。訳さない（訳すと、似た名前の別の種と取り違えやすい）。データに無ければ、クラス名と見た目で書く（例 `白い大型の犬`）。「写っていない」「〜だけ」「どれでもない」「ばかり」「1枚も」と書く画像は、元の写真を1枚ずつ Read で開いて探し、1枚も外れないときだけ書く（lint が `image-absolute` で知らせる）。小さすぎて決められないときは、決められないと書き、そのクラスを `unsure` に入れる。**「写っていない」「〜以外」と数えるときは `imgfig.absent(it, クラス)` で数え、決めきれない写真は「決めきれない」として別に数える**（タイトル・箇条書きの枚数にも入れない）。説明（`imgfig.seen`）には決めきれない対象が「犬?」と出る。説明・`note` には写真で見えることだけを書き、種の知識で補わない（写っていない牙・角・鳴き声・行き先などを書かない）。
8. **データのラベルも疑う**: 人手で付けた正解ラベルにも誤りがある。元の写真で見て、ラベル（や撮影者の題名）と写っているものが合わない画像は、黙ってラベルどおりに扱わない。誤りの分析では「ラベルの誤り」と「モデルの誤り」を分けて数える。「ラベルの誤り」とするのは、ラベルのクラスが写真のどこにも写っていないことを元の写真で確かめたときだけ。ラベルのクラスと予測のクラスが両方写っていれば「両方写る」として別に数える（どちらの誤りでもない）。混同行列など数だけのスライドでも、ラベルで数えた枚数を「犬の写真」「犬が写る」と書かない。ラベルの数は「ラベルが犬の写真」と書き、写っている数は確認の表で数える（render_check が、ラベルの数と同じで確認の表の数と違う「N枚は犬の写真」を知らせる）。表示するラベルを直すときは `data/label_fix.csv`（id, 直したラベル, 理由）に残して付録に書き、タイトルの数字が変わらないかを確かめる。
9. **小さく写る対象は、拡大して見せる**: 主張に関わる対象が写真の一部に小さく写る（端・奥・物の陰）ときは、`imgfig.zoom_figure` で写真全体（枠つき）と、元の写真から切り出した拡大を並べる。縮小画像のままでは聴衆に見えない。枠は `imgfig.py locate` の目盛りつき画像で位置を読んで決め、描いた図を Read で開いて、枠の中に対象が入っていることを確かめる。

| 切り口 | 群の作り方 | タイトルの例 |
|---|---|---|
| 閾値の移動 | 2本の線の間にいる画像 × 正解（`moved`・`moved_figure`） | 線を1%から5%へ動かすと、犬6枚を失って犬以外40枚を除ける |
| 正解×予測 | 誤った画像を（正解, 予測）で `split_by` | 傷ありを見逃した8枚は、すべて端の小さな傷だ |
| 変更の前後 | 前後で結果が違う画像を（前, 後）で `split_by` | 新しいモデルで12枚が直り、3枚が新たに誤りになる |
| スコアの順 | 上位・境界・下位を `pick` | 確信度が最も低い20枚の半分は、暗い写真だ |
| 群ごとの代表 | 型・クラスタ・期間で `split_by` し、各群から `pick` | 投稿写真は5つの型に分かれ、最多は店内の写真だ |
| 基準の両側 | 該当・非該当・迷う例を並べる | 「対象外」にするのは、店の文脈が写っていない写真だ |
| 似たもの | 1枚と、その近傍や典型例（`rows_figure` の見出しを Item にする） | 見逃した傷は、汚れの写真に最も近い |

表にない切り口でも手順は同じ: 群を作る → 枚数を数える → 並べる → 選び方を書く。
誤りや変化を数えるときは、正解ラベルのほうが違う画像が混じっていないかを画像で確かめ、混じっていれば分けて数える。

- 重い処理（ダウンロード・埋め込み計算・推論）はデッキのフォルダの `prepare.py` に分け、結果の表とサムネイル（`data/`）をコミットする。qmd は結果を読むだけにして、描画に重い依存を持ち込まない。実行は `uv run --no-project --with … python prepare.py`。
- 第三者の画像は、ライセンスと作者を記録し（`data/credits.csv`）、作者・出典の一覧（`credits.html`）を YAML の `resources:` でデッキと一緒に公開する。公開するデッキでは、顔の分かる人物・読めるナンバープレートなどが写る画像を目視で外し、外した画像と理由を `exclude.csv` に残す。
- 他人のデータでモデルを動かす前に、そのデータの決まり（事前登録・評価用データの隔離など）を確かめる。決まりに触れるなら、別の独立したデータで作る。
- 規約と理由は `references/style_guide.md` の「具体例の画像で説明する」、見本は `decks/2026-09-30-outlier-threshold-images/`（閾値の移動）。

## フェーズ4: 検証

1. `python3 .claude/skills/slides/scripts/lint_slides.py decks/<name>/index.qmd` を自分で走らせ、block を 0 にする。
2. 直すのは違反したスライドだけ（Edit で該当箇所を置換）。デッキ全体を再生成しない。
3. 写真を並べたスライドは、主張（タイトル・箇条書き・見出し・画像ごとの説明）ごとに、該当する画像を `imgfig.py sheet`（元の写真があればそれ）で見て、主張と合うかを1件ずつ確かめる。とくに「〜だけ」「どれでもない」「ラベルの誤り」の画像は、元の写真を1枚ずつ開く。スクショの縮小画像で済ませない。
4. `.claude/skills/slides/scripts/render_check.sh decks/<name>` で全枚を PNG にし、全枚を Read で目視する。写真の図があれば、図の説明と群の見出しを確認の表（`data/look.csv`）と照らした食い違い、拡大で確かめていない写真、ラベルの数を写真の中身として書いた文、`imgfig.claim` で確かめていないタイトルの枚数、claim の文と写真の食い違いが WARNING で出るので、0件にする。はみ出し・折り返し崩れ・フォント崩れ・読めない図を探し、見つけたら該当スライドだけ直す。画像を並べた図は、スライド上での1枚の大きさの目安が図ごとに表示される。「小さい」と出た図は、見せる枚数を減らすか、図を分ける。図の合計サイズと1MB超の図も表示される。
5. 最後に `quarto render decks/<name>/index.qmd`（必要なら `--to pptx`／`--to beamer`）で出力する。公開まで頼まれているときは `scripts/publish.sh`。
6. ターン終了時に Stop hook が同じ lint を走らせる。block されたら理由に書かれた枚だけを直す。
7. lint や図の関数を直したら `.venv/bin/python -m unittest discover -s tests` を通す。

## やらないこと（理由）

- 一発で全枚を生成しない: 段階生成の方が読みやすさの評価が高く（小規模評価）、承認前の本文は捨てることになる。
- 「簡潔に」と自分に言い聞かせて済ませない: 長さは数値上限と lint でしか安定して抑えられない。
- 規約の文面や本人への指示文をスライド本文に流用しない: 本文は聴衆に向けた事実と結論だけで書く。
- 都合のよい画像だけを選んで見せない: 読み手は見せられた例から全体を推測する。全数か、書いてある規則で選ぶ。
