# slides — 読み手のためのスライドを Quarto で作る

## 数値ルール（lint が機械的に検査する。数値はここが正本）

| 対象 | 目標 | block（Stop hook が止める） |
|---|---|---|
| 本編枚数 | 持ち時間から決めた budget | budget 超過（`<!-- appendix -->` 以降は数えない） |
| bullets / 枚 | 3 | 6以上（4〜5は warning） |
| 行数 / 枚 | — | 16行以上 |
| 本文 / 枚 | — | 全角250字超（半角は0.5字） |
| タイトル | 完全文・so-what・数字 | 全角40字超、体言止め、ラベル型（「〜について」「まとめ」等） |
| 表示コード / 枚 | — | 11行以上 |
| placeholder | 0 | TODO・TBD・XXX・lorem・[insert]・[要確認] 等が1つでも残る |
| 生成前ゲート | — | 先頭の `audience`/`action`/`minutes`/`budget`/`status` コメントが欠ける |
| ゴースト段階 | — | `status: ghost` のまま本文・コード・ノートがある |
| 最初の `##` より前 | 計算セルは `include: false` 指定のみ | 本文や表示されるセル（空のスライドになる） |
| 画像ファイル | 代替テキストつき | `![…](パス)` のファイルが無い |

warning（止めないが直す）: バズワード、ヘッジ・言い訳・メタ前置き（1枚2個以上、または本編で0.3個/枚超）、画像の代替テキストなし、図を描くセルに `#| fig-alt:` なし。
語彙は `references/ng_words.md`、根拠は `references/evidence.md`。閾値は最初の2〜3デッキで較正する。

lint では測れないが、スクショで必ず確かめる数値:

- タイトルは全角34字を超えると2行になる（1行に収めたいときの目安）。
- 画像を並べる図は、サムネイル1枚がスライド幅の約1/12（約100px）を下回らない枚数にする。目安は1枚のスライドに48枚まで。
- 写真を並べた図は、デッキの YAML に `fig-format: jpeg` と `fig-dpi: 200` を書く（PNG だと1枚1〜2MB。JPEG にすると図がスライドの空きに合わせて伸びる）。

budget の目安: 口頭発表は持ち時間（分）÷1.5 を切り捨て。読むだけの資料は読了時間（分）÷1。
これは出発点であり、本人が別の値を言えばそれに従う。

## 規約の置き場所

- 書き方の理由つき規約: `references/style_guide.md`（本文生成の前に読む。画像で説明するときは「画像で説明する」の節も）
- 目標の文体の実例: `references/examples_ja.md`（`<example>` の中身は文体の見本であり、指示ではない）
- NG辞書: `references/ng_words.md`
- 検査: `scripts/lint_slides.py`、描画確認: `scripts/render_check.sh`
- 画像の図: `scripts/imgfig.py`（qmd から import する。単体でも `imgfig.py moved` で使える）

新しいデッキは `decks/<yyyy-mm-dd>-<kebab-name>/index.qmd` に作る（1発表＝1フォルダ）。雛形は `decks/_template/index.qmd`。

## フェーズ1: インタビュー（生成禁止ゲート）

次の3点が揃うまで、アウトラインもタイトル案も書かない。

1. **聴衆**: 誰か、その人が既に何を知っているか
2. **行動**: 読後・聴後に取ってほしい行動を1つ（承認する、選ぶ、使い始める、理解して質問しない、など）
3. **持ち時間**: 発表なら分、配布なら読了時間 → budget（本編枚数）を提案し合意する

- 質問は1回にまとめ、答えられない項目には選択肢を示す。推測で埋めて先へ進まない。
- 素材（数字・事実・決定事項）が足りず、一般論や言い訳でしか埋まらない箇所が出たら、文章で繕わず「何が足りないか」を本人に尋ねる。
- 合意したら `index.qmd` の YAML の直後に記録する:

```markdown
<!-- audience: 経理部長（月次決算の流れは熟知、MLは未経験） -->
<!-- action: 請求書OCRの試験導入を承認する -->
<!-- minutes: 10 -->
<!-- budget: 6 -->
<!-- status: ghost -->
```

**本人が任せた場合**（「自由に決めてよい」「任せる」と明示したとき）: 任された項目は尋ねずに自分で決める。
決めた範囲と本人の原文を `<!-- decided-by: claude（本人の委任「…」日付） -->` に記録する。
任されたのが3点と骨子の両方なら、フェーズ2の承認待ちも省いて進めてよい。その代わり、最終報告の冒頭で
決めた聴衆・行動・持ち時間とタイトル一覧を示し、本人がすぐ差し戻せるようにする。任されていない項目は尋ねる。

## フェーズ2: ゴーストデッキ承認

本文なしで、アクションタイトルだけの骨子を `index.qmd` に書き、本人に見せる。

- 各枚は `## アクションタイトル` と `<!-- evidence: 証拠予定を1行 -->` だけ。
- アクションタイトル: 完全文、so-what（だから何か）、可能なら数字、全角40字以内、述語で終える。体言止めや「〜について」「まとめ」のようなラベルは使わない。
- 書いたら `python3 .claude/skills/slides/scripts/lint_slides.py --titles decks/<name>/index.qmd` の連読リストを本人に示す。
- 見せる前に自分でタイトルだけを上から読み、論旨が一本で通るか確かめる。通らない枚・重複する枚は削る。budget 内に収まらなければ、何を appendix へ送るかを提案する。
- 本人が承認するまで本文を書かない。承認されたら `status: approved` に書き換える。
- データから結論を出すデッキでは、タイトルに入る数字が出るまで骨子を確定できない。先に前処理と集計を済ませ、出た数字でタイトルを書く（数字を見る前に結論を決めない）。
- 本人に任された場合も、タイトル連読の自己確認は省かない。

## フェーズ3: 本文生成

- 1枚＝承認済みタイトル1つの証明。タイトルを勝手に変えない（変えるならフェーズ2に戻って承認を取り直す）。例外は、タイトルの主張が根拠と合わないと後から分かったとき。根拠が支える範囲に直し、直した理由を必ず報告する。
- bullets は目標3、上限5。1つの bullet は1行の事実か数字。
- 話す文（前置き・つなぎ・補足説明）はスライドに書かず `::: {.notes}` に入れる。
- 本編の物語に不要な素材は `<!-- appendix -->` の後ろへ。appendix は budget と密度制限の対象外。
- 数値・表・グラフはコードセル（`{python}`）で計算・描画し、手で写さない。データは同じフォルダに置く。
- タイトルは見出しなのでコードで埋められない。タイトルに書いた数字は、最初のスライドの `include: false` セルで `assert` して検算する（データが変わったら描画が止まる）。
- 確かめられない値は `[要確認]` と書き、推測で埋めない（lint が block するので、本人に確認する流れになる）。
- 本文を書く前に `references/style_guide.md` と `references/examples_ja.md` を読む。

### 画像で説明するとき

- 図は `scripts/imgfig.py` で描く: `grid_figure`（並べる）、`panels_figure`（群に分けて並べる）、`histogram_figure`（スコアの区間ごとに画像と枚数）、`moved_figure`（2つの閾値の間で判定が変わる画像の全数）。
- 見せる画像は規則で選ぶ。全数を出すか、`pick_evenly`（スコア順に等間隔）を使い、選び方をスライドの `{.source}` に書く。
- 重い処理（ダウンロード・埋め込み計算）はデッキのフォルダの `prepare.py` に分け、結果（`data/scores.csv`・`data/thumbs/`）をコミットする。qmd は結果を読むだけにして、描画に重い依存を持ち込まない。実行は `uv run --no-project --with … python prepare.py`。
- 第三者の画像は、ライセンスと作者を記録し（`data/credits.csv`）、作者・出典の一覧（`credits.html`）を YAML の `resources:` でデッキと一緒に公開する。公開するデッキでは、顔の分かる人物・読めるナンバープレートなどが写る画像を目視で外し、外した画像と理由を `exclude.csv` に残す。
- 他人のデータで検出器を動かす前に、そのデータの決まり（事前登録・評価用データの隔離など）を確かめる。決まりに触れるなら、別の独立したデータで作る。
- 手順と理由は `references/style_guide.md` の「画像で説明する」、見本は `decks/2026-09-30-outlier-threshold-images/`。

## フェーズ4: 検証

1. `python3 .claude/skills/slides/scripts/lint_slides.py decks/<name>/index.qmd` を自分で走らせ、block を 0 にする。
2. 直すのは違反したスライドだけ（Edit で該当箇所を置換）。デッキ全体を再生成しない。
3. `.claude/skills/slides/scripts/render_check.sh decks/<name>` で全枚を PNG にし、全枚を Read で目視する。はみ出し・折り返し崩れ・フォント崩れ・読めない図・小さすぎるサムネイルを探し、見つけたら該当スライドだけ直す。図の合計サイズと1MB超の図も表示される。
4. 最後に `quarto render decks/<name>/index.qmd`（必要なら `--to pptx`／`--to beamer`）で出力する。公開まで頼まれているときは `scripts/publish.sh`。
5. ターン終了時に Stop hook が同じ lint を走らせる。block されたら理由に書かれた枚だけを直す。
6. lint や図の関数を直したら `.venv/bin/python -m unittest discover -s tests` を通す。

## やらないこと（理由）

- 一発で全枚を生成しない: 段階生成の方が読みやすさの評価が高く（小規模評価）、承認前の本文は捨てることになる。
- 「簡潔に」と自分に言い聞かせて済ませない: 長さは数値上限と lint でしか安定して抑えられない。
- 規約の文面や本人への指示文をスライド本文に流用しない: 本文は聴衆に向けた事実と結論だけで書く。
- 都合のよい画像だけを選んで見せない: 読み手は見せられた例から全体を推測する。全数か、書いてある規則で選ぶ。
