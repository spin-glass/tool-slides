# 評価の手引き（評価者に渡す文面）

あなたはスライド資料の評価者です。同じ依頼に対して作られた複数のデッキを、聴衆の立場で評価してください。
どのデッキを誰がどう作ったかは伏せてあります。推測せず、画面に見えるものだけで判断してください。

## 依頼の内容（全デッキ共通）

- 目的: 画像分類のモデルを新しい版に替えると判定がどう変わるかを、実際の画像を使った具体例で説明する。どの画像が直り、どの画像が新たに間違うようになったのかを見せる
- 聴衆: 画像分類を運用するチーム（エンジニアとアノテーター）。新旧の正解率（88% と 87%）は知っているが、どの画像の判定が変わったかは見たことがない
- 聴いた後にしてほしいこと: 新しい版に切り替えるかどうかを、判定が変わった画像を見てから決める
- 持ち時間: 口頭で10分
- 題材: 牧場の動物6クラス（羊・ヤギ・アルパカ・鹿・牛・馬）、評価用240枚を新旧2つの版で判定した結果

## 見るもの

`<フォルダ>/<デッキ記号>/slide-01.png, slide-02.png, …` が、そのデッキの全スライド（発表順）です。
各デッキの全スライドを Read で開いて見てから採点してください。発表者ノートは見えません（聴衆と同じ条件です）。

## デッキごとに答えること

事実の確認（見えるものを数える・有無を答える）:

- `n_slides`: スライドの総数（表紙を含む）
- `n_changed_images`: 新旧で正誤が変わった画像（直った画像と、新たに誤った画像）を、画像として見せている枚数の合計（同じ画像の再掲は数えない。おおよそでよい）
- `pick_rule`: 見せる画像の選び方（全数・抜粋の基準など）がスライドに書かれているか（true / false）
- `contrast`: 直った画像と新たに誤った画像の両方を見せているか（true / false）
- `credit`: 写真の出典やライセンスの記載があるか（true / false）
- `broken_slides`: はみ出し・重なり・小さすぎて読めない文字や画像があるスライドの枚数

5段階の評価（1 = まったく当てはまらない、3 = どちらとも言えない、5 = よく当てはまる）:

- `audience`: 聴衆に合っている（すでに知っていることを長く説明せず、知らないことを見せている）
- `images`: どの画像が直り、どの画像が新たに誤るようになったか、それがどんな画像かが、画像を見て分かる
- `titles`: スライドのタイトルだけを順に読んで、話の筋が通る
- `economy`: 量が10分に収まり、余計な説明・前置き・言い訳がない
- `layout`: 見た目に破綻がなく、文字も画像も読める
- `action`: 聴いた後に何をすればよいかが分かる
- `overall`: この資料を10分の発表にそのまま使える

`comment`: 採点の理由を1〜2文（そのデッキの最も良い点と最も困る点）。

## 出力

最後に、次の形の JSON だけを出してください（デッキ記号をキーに）。

```json
{"A": {"n_slides": 0, "n_changed_images": 0, "pick_rule": false, "contrast": false, "credit": false, "broken_slides": 0,
       "audience": 3, "images": 3, "titles": 3, "economy": 3, "layout": 3, "action": 3, "overall": 3, "comment": "…"},
 "B": {}}
```

# 記述の正しさの確認（別の評価者に渡す文面）

あなたは事実確認の担当です。同じ依頼に対して作られた複数のデッキについて、スライドが「新旧で判定が変わった画像はどんな画像か」を
述べている箇所を拾い、参照図と照らして正しいかを確かめてください。どのデッキを誰がどう作ったかは伏せてあります。

- 参照図: 新旧で正誤が変わった28枚の全数。1枚目は直った12枚、2枚目は新たに誤った16枚で、正解クラスと予測の組ごとに並べてある。各画像の下は旧版と新版の予測と確信度
- デッキ: `<フォルダ>/<デッキ記号>/slide-NN.png`

デッキごとに、画像の中身についての記述（例:「直ったのは岩場にいる動物の写真だ」「新たに誤ったのは群れが遠くに小さく写った写真だ」
「正解ラベルの方が誤っている」）を1件ずつ拾い、参照図の該当する組の画像を見て、次のどれかに分けてください。
枚数や割合など数字だけの記述は対象外です。切り替えるかどうかの提案も対象外です。

- `supported`: 参照図の画像の多くに当てはまる
- `unsupported`: 参照図の画像に当てはまらない、または一部にしか当てはまらないのに全体のこととして述べている
- `uncheckable`: 参照図からは確かめられない

出力は次の形の JSON だけにしてください。

```json
{"A": {"claims": [{"text": "…", "verdict": "supported"}], "n_supported": 0, "n_unsupported": 0, "n_uncheckable": 0,
       "main_finding_correct": true, "comment": "…"}}
```

`main_finding_correct` は、そのデッキの中心の説明（直った画像・新たに誤った画像がどんな画像かの説明）が参照図と合っているか。
